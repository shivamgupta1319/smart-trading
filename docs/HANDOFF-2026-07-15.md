### The three fixes that mattered

1. **F1 — 20 cells could never fire, ever.** Scanner fetched `"150d"` ≈ **102 bars** while strategies
   guard at 200–250 → silent all-zeros. Proven by natural experiment (every >102-bar strategy: 0 live
   signals; every ≤60-bar control: fires). Now `"2y"` ≈ **498 bars, verified on the live scanner**.
   Irony: the guards were added to fix a *crash*, and created a silent death.
2. **F2 — Episodic_Pivot was mathematically dead.** It raised `consolidation_high` to include
   `highs[i]` then tested `close > consolidation_high` ⇒ `close[i] > high[i]`. 15 reports, **0 trades
   ever**. Now **32 trades across 14 cells**.
3. **F3 — the honest metric was computed and thrown away.** `avgRMultiple` (base.py's own comment:
   *"the honest edge metric to rank cells on"*) was never persisted, so everything ranked on ROI —
   raw-cumulative and window-dependent (1D ≈5.1y vs 15m/5m ≈4.7mo ⇒ **~13× incomparable**).

**Both bug fixes have tests proven to FAIL against the original code**, not just pass against the fix
(`"150d"` → *"yields ~102 bars … the F1 bug is back"*). The F1 test parses the **real** guards out of
`strategies/`, so a hungrier strategy breaks the build instead of dying silently. **28 passed / 1 skipped.**

## Gotchas learned this session

- **The shell is zsh: unquoted `$VAR` does NOT word-split.** Bit me twice — `docker run $FLAGS`
  passed the whole string as one arg and the env silently never applied, producing "identical"
  results that looked like a finding. **Inline docker flags; never build them in a variable.**
- **`run-backtest` returns metrics nested under `"metrics"`**, not at top level.
- **Both ends of an attribution ladder must reconcile** or the middle means nothing. Gate A's only
  failures were Episodic_Pivot — which independently confirmed F2 from a different direction.
- **Guards that turn "not enough data" into "no signal" are dangerous** (F1). Prefer raising.
- **Don't ship an exit-model change off a one-symbol spot-check** — that's how the time-stop shipped.
  The INFY check hinted at it and I under-weighted it. Run the ladder.
- **`ENGINE_VERSION` is `2026.07.15-f3`**, so pre-existing reports are stale by design.
- **Adding a Stock is safe** — `stocks.service.create` inserts a row only; the scanner iterates
  `ActiveConfiguration`, so nothing goes live. Cost is the nightly fetch + a bigger Run All.
